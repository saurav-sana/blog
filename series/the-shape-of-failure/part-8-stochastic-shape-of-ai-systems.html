The Stochastic Shape of AI Systems

Token Sampling, Inference Queues, and the Compounding Failure of Autonomous Agents.

October 28, 2026 · AI Engineering & Orchestration

"You are trying to wrap five nines of reliability around a piece of software that fundamentally works by rolling dice very, very fast."

— Anonymous Staff Engineer

In classical distributed systems, uncertainty is an environmental hazard—we build deterministic state machines and try to protect them from chaotic networks. In modern AI architectures, uncertainty is the compiler itself.

Large Language Models do not "execute" code in the traditional sense; they sample from categorical probability distributions over vocabularies. When you introduce agentic loops—where an LLM writes a database query, executes a tool, parses the response, and plans the next step—you take standard software failure rates and exponentiate them.

The Anatomy of LLM Failures: TTFT vs. TPOT

Before we can engineer fault tolerance into an agent, we must separate infrastructure failure from semantic failure. They require entirely different mitigation strategies. Conflating the two is how you accidentally trigger a retry storm that takes down your entire inference cluster.

TTFT (Serving Queue)

Time To First Token. This is compute-bound. It measures the pre-fill phase where the KV-cache is allocated for the prompt. When the cache overflows, requests queue up. This failure is deterministic and behaves exactly like standard web traffic saturation.

TPOT (Decoding Phase)

Time Per Output Token. This is memory-bandwidth bound. Once generating, TPOT typically degrades gracefully under load until it hits a cliff. High TPOT means the model is working, just starving for memory IOPS.

Semantic Drift

Token Sampling Variance. The model generates valid JSON, but confidently hallucinates a non-existent parameter. This is stochastic. Retrying blindly without changing temperature or prompts rarely fixes this.

The Mathematics of Agentic Compounding

If you build a ReAct (Reasoning + Acting) agent that needs to execute N independent reasoning steps to fulfill a user request, the probability of the entire workflow succeeding is exactly the same binomial logic we explored in Part 2, but applied to logical steps: $P_{success} = (P_{step})^N$.

When engineers transition from single-prompt chatbots to Agentic RAG or multi-step orchestration frameworks (like LangGraph or DSPy), they are often stunned by the sudden drop in reliability. A prompt that works 92% of the time feels "production ready." But an agent that relies on that prompt 6 times in a loop will fail nearly half the time.

Architectural Patterns for Fault-Tolerant Agents

The KV-Cache Eviction Cliff

Blindly retrying a failed agent step is dangerous. Because LLM generation is highly stateful, an agent stuck in a retry loop (e.g., trying to fix a malformed JSON output by asking the model to "try again") consumes enormous KV-cache memory on the inference server. If just 5% of your agents get stuck in loops, they will evict the cache for the other 95%, causing a catastrophic, system-wide latency spike.

To survive compound failure rates without taking down the infrastructure, autonomous pipelines require entirely different circuit breakers than standard microservices.

1. Constraint-Guided Decoding

Never rely on "prompt engineering" to guarantee JSON schemas or enum selections. Use grammar-constrained decoding at the inference engine level. By masking the logits during decoding, you force the probability of a structural formatting failure to zero, entirely eliminating one class of semantic drift.

2. Deterministic Anchoring (GraphRAG)

Stochastic models drift when they have to maintain complex entity relationships in their context window over long conversations. A robust pattern is to anchor the agent's memory in deterministic data structures. By integrating a Graph database (like Neo4j) to map relationships deterministically, the LLM is relegated to translating the graph's hard facts into natural language, rather than hallucinating the facts itself.

3. Semantic Circuit Breakers

HTTP 500s are easy to catch. But what if the model returns HTTP 200 with the payload: "I'm sorry, I cannot fulfill that request."? Your downstream agentic parser will crash trying to extract a SQL query from that sentence. Fault-tolerant agents implement "Semantic Circuit Breakers"—fast, regex-based or lightweight classifier checks that evaluate the intent of the response before passing it to the next node in the orchestration graph.

4. SLM Fallback Routing

When an agent step fails, hitting the primary, massive LLM again with an exponential backoff often just adds pressure to an already saturated TTFT queue. A highly effective resilience pattern is routing validation and simple retries to local Small Language Models (SLMs). Dedicated, fine-tuned models like Gemma or Qwen running via Ollama can act as fast, cheap fallback validators to un-stick a stalled agent loop without consuming the primary cluster's KV-cache.

We spent the earlier parts of this series learning to tame the chaos of hardware, network partitions, and queuing theory. With AI, we are inviting stochastic chaos directly into the application logic layer. The math of failure hasn't changed; we just have to apply it to our prompts, our orchestration graphs, and our token sampling strategies.
