Mapping the Shape of Failure to LLM Infrastructure

December 5, 2026 · Appendix · AI/LLM Frontier

“All models are wrong, but some are useful.”

— George E. P. Box, Statistician

Welcome to the appendix. This is not a lookup table that prescribes a probability distribution merely because a system invokes an LLM. That is statistical cargo-culting.

Instead, this is a translation guide. It maps the abstract mathematics of the previous eight parts to the observable, empirical realities of AI infrastructure. Use it as an architectural decision aid: a way to verify capacity models, interrogate assumptions, and enforce system invariants when the underlying model is a stochastic black box.

The Golden Rule of AI SRE

When an AI system fails, the first question is never "Which distribution does this follow?" It is: "What physical process generated this observation, and what architectural control prevents it from taking down the system next time?"

Interactive Translation Matrix

Select an LLM subsystem below to inspect the underlying stochastic process, the telemetry metrics that actually matter, the SRE trap to avoid, and the control mechanism required to maintain system invariants.

Inference Serving (TTFT & Throughput)

Poisson (Arrivals) + Exponential / Heavy-Tail (Queue Wait)

Uncoordinated prompt arrivals follow a Poisson process (Exponential inter-arrival times). As GPU utilization approaches saturation, variable prompt prefill lengths turn an M/M/c queue into an M/G/c bottleneck.

Metrics to Watch:

  • Time to First Token (TTFT) p95 / p99
  • Inter-Token Latency (ITL)
  • KV-Cache Utilization % & Preemption Rate

The SRE Trap

Sizing your GPU cluster based on average RPS and mean prompt tokens. When a Poisson traffic burst coincides with a long-context prefill, head-of-line blocking causes queue wait times to diverge non-linearly.

The Engineering Control

Continuous batching with chunked prefill (vLLM/TGI) to prevent head-of-line blocking, paired with strict admission control (load shedding) when KV-cache occupancy crosses 85%.

The Verification Workflow

You cannot fix what you cannot measure, and you cannot measure what you cannot explain. When an AI system degrades in production, follow this deterministic diagnostic sequence:

The Post-Mortem Protocol
  1. Observe the Tails: Discard averages. Inspect p50, p95, and p99 latencies alongside the joint distribution of input prompt tokens and output generation lengths.
  2. Isolate the Boundary: Pinpoint where the invariant broke—was it in the inference engine (KV-cache thrashing), the retrieval layer (HNSW tail latency), or the orchestration parser (malformed JSON)?
  3. Identify the Physical Mechanism: Map the symptom to hardware or algorithmic reality. Was it head-of-line blocking from a 100k-token prefill? Compounding error decay across a 12-step agent loop? A retry storm amplifying load?
  4. Apply the Architectural Control: Enforce the deterministic constraint (chunked prefill, token-based rate limiting, grammar-constrained decoding, or hard circuit breaking) that bounds the failure mode mathematically.

The frontier of AI infrastructure demands more systems rigor than traditional distributed architectures, not less. A relational database either commits the transaction or aborts it. An LLM will happily return a syntactically valid payload that is semantically hallucinated—after burning 4,000 GPU milliseconds. Use the math. Trust the telemetry. And always build the circuit breaker.
