Mapping the Shape of Failure to LLM Infrastructure

December 5, 2026 · Appendix · AI/LLM Frontier

“All models are wrong, but some are useful.”

— George E. P. Box, Statistician

Welcome to the appendix. This is not a lookup table that prescribes a probability distribution merely because a system invokes an LLM. That is statistical cargo-culting.

Traditional deterministic query engines guarantee reproducible execution paths given identical state (though they can still fail via stale Iceberg snapshots, schema drift, or broken SQL logic). Contrast this with AI systems, where both the execution runtime (stochastic queueing, dynamic continuous batching, KV-cache eviction) and the output generation mechanism itself (autoregressive token sampling, semantic grounding) are non-deterministic.

This is a translation guide. It maps the abstract mathematics of the previous eight parts to the observable, empirical realities of AI infrastructure. Use it as an architectural decision aid: a way to verify capacity models, interrogate assumptions, and enforce system invariants when the underlying model is a stochastic black box.

The Golden Rule of AI SRE

When an AI system fails, the first question is never "Which distribution does this follow?" It is: "What physical process generated this observation, and what architectural control prevents it from taking down the system next time?"

Core AI Infrastructure Equations

To safely provision, admission-control, and evaluate AI workloads, architects must explicitly bind abstract stochastic boundaries to physical constraints.

1. KV-Cache Memory Allocation & Preemption

Continuous batching queues operate on physical HBM. The per-token memory footprint for Key-Value caching dictates how many active tokens the GPU can support before triggering catastrophic sequence preemption.

\[ M_{\text{token}} = 2 \cdot L_{\text{layers}} \cdot H_{\text{kv}} \cdot d_h \cdot b_{\text{bytes}} \]
  • \(2\): Accounts for both Key and Value tensors.
  • \(L_{\text{layers}}\): Transformer layer depth.
  • \(H_{\text{kv}}\): Number of KV heads (reflecting GQA/MQA efficiency).
  • \(d_h\): Head dimension.
  • \(b_{\text{bytes}}\): Precision byte-width (e.g., \(2\) for FP16, \(1\) for FP8).

Architectural Application: Do not use fixed request-concurrency limits. Calculate the absolute token capacity \(M_{\text{max}} / M_{\text{token}}\) and enforce token-budget admission control (e.g., illustrative load-shedding at 85% HBM occupancy).

2. Semantic Evaluation & LLM-as-a-Judge Noise

When using an LLM to evaluate semantic correctness, the judge itself is an imperfect stochastic classifier. Raw dashboard pass rates (\(p_{\text{obs}}\)) must be adjusted for the judge's False Positive rate (\(\alpha_{\text{fp}}\)) and False Negative rate (\(\beta_{\text{fn}}\)) using the Rogan-Gladen prevalence adjustment:

\[ \hat{p}_{\text{true}} = \frac{p_{\text{obs}} - \alpha_{\text{fp}}}{1 - \alpha_{\text{fp}} - \beta_{\text{fn}}} \]

For small sample evaluation sets, report the Wilson Score Interval rather than naked point estimates to capture epistemic uncertainty:

\[ \text{Interval} = \frac{\hat{p} + \frac{z^2}{2n} \pm z\sqrt{\frac{\hat{p}(1-\hat{p})}{n} + \frac{z^2}{4n^2}}}{1 + \frac{z^2}{n}} \]

The Verification Workflow

You cannot fix what you cannot measure, and you cannot measure what you cannot explain. When an AI system degrades in production, follow this deterministic diagnostic sequence:

The Post-Mortem Protocol
  1. Observe the Tails: Discard averages. Inspect p50, p95, and p99 latencies alongside the joint distribution of input prompt tokens and output generation lengths.
  2. Distinguish Structural from Semantic Failure: A perfectly formed JSON object (guaranteed by Categorical logit masking) that contains hallucinated facts is a semantic failure, not a structural serving failure. Do not solve semantic issues with infrastructure retries.
  3. Isolate the Boundary: Pinpoint where the invariant broke—was it in the inference engine (KV-cache thrashing), the retrieval layer (HNSW tail latency), or the orchestration parser?
  4. Identify the Physical Mechanism: Map the symptom to algorithmic reality. Was it head-of-line blocking from a 100k-token prefill? Compounding state contamination across a 12-step agent loop?
  5. Apply the Architectural Control: Enforce the deterministic constraint (chunked prefill, token-based rate limiting, grammar-constrained decoding, or circuit breaking) that bounds the failure mode mathematically.

The frontier of AI infrastructure demands more systems rigor than traditional distributed architectures, not less. A relational database either commits the transaction or aborts it. An LLM will happily return a syntactically valid payload that is semantically hallucinated—after burning 4,000 GPU milliseconds. Use the math. Trust the telemetry. And always build the circuit breaker.
